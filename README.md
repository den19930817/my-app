# Тренировочный план · Flutter / Dart

Flutter-приложение: недельный план, добавление и удаление упражнений, подходы, вес и результаты, отметки выполнения, перенос и копирование на другой день, «Скопировать со вчера».

## Разработка

Flutter **3.35.7** (Dart из этого SDK). Из корня проекта:

```sh
flutter pub get
flutter run -d chrome
```

Для облачной среды без интерактивного браузера:

```sh
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 3000
```

## Проверки и сборка

```sh
dart format lib test
flutter analyze
flutter test
flutter build web --release --base-href /my-app/ --no-web-resources-cdn --pwa-strategy=none
```

Готовый сайт находится в `build/web`. Для локальной проверки сборки с префиксом `/my-app/` разместите этот каталог под таким же путём веб-сервера. Для запуска из корня сайта соберите с `--base-href /`.

## Данные

План хранится локально через `shared_preferences`, аккаунта и синхронизации нет. Веб-версия при первом запуске импортирует старый JavaScript-план из ключа localStorage `training-plan-v1` в новый ключ Flutter, сохраняя исходную запись. Миграция работает при открытии в том же браузере и на том же домене. Повторный запуск использует уже изменённый Flutter-план. Старые данные не удаляются.

Копирование сохраняет исходную тренировку. Перенос освобождает исходный день. Оба действия сохраняют все поля и добавляют упражнения к существующим в выбранном дне. В полях веса и результата можно указать значения для каждого подхода через `/`. «Сегодня» и «вчера» определяются по локальному времени устройства.

## GitHub Pages

Workflow `.github/workflows/flutter-web.yml` при изменениях `main` устанавливает фиксированный Flutter SDK, запускает анализ и тесты, собирает сайт и записывает только готовую сборку в `gh-pages`, сохраняя историю ветки. В **Settings → Pages** остаётся источник **Deploy from a branch → gh-pages → / (root)**.

GitHub не запускает branch-based Pages build от коммитов, созданных `GITHUB_TOKEN`. После успешного workflow требуется коммит в `gh-pages` от пользователя (достаточно пустого коммита) либо переключение на публикацию через официальный Pages Actions workflow. В текущем процессе завершающий коммит публикации отправляется из облачной среды после проверки `source-revision.txt`.
