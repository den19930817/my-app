# Тренировочный план · Flutter / Dart

Flutter-приложение: недельный план, добавление и удаление упражнений, подходы, вес и результаты, отметки выполнения, перенос и копирование на другой день, «Скопировать со вчера».

## Разработка

Flutter **3.35.7** (Dart из этого SDK). Из корня проекта:

```sh
flutter pub get
flutter run -d chrome
```

Для облачной среды без интерактивного браузера:

```sh
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 3000
```

## Проверки и сборка

```sh
dart format lib test
flutter analyze
flutter test
flutter build web --release --base-href /my-app/ --no-web-resources-cdn --pwa-strategy=none
```

Готовый сайт находится в `build/web`. Для локальной проверки сборки с префиксом `/my-app/` разместите этот каталог под таким же путём веб-сервера. Для запуска из корня сайта соберите с `--base-href /`.

## Данные

План хранится локально через `shared_preferences`, аккаунта и синхронизации нет. Новый формат подходов использует ключ `training-plan-flutter-v2`. При первом запуске он импортирует последний Flutter-план из `training-plan-flutter-v1`, а при его отсутствии — старый JavaScript-план из localStorage `training-plan-v1`. Исходные записи сохраняются отдельно: старая вкладка приложения не перезапишет новый формат. Миграция работает при открытии в том же браузере и на том же домене. Повторный запуск использует уже изменённый Flutter-план. Старые данные не удаляются.

Копирование сохраняет исходную тренировку. Перенос освобождает исходный день. Оба действия сохраняют все поля и добавляют упражнения к существующим в выбранном дне. При добавлении упражнения выберите от 1 до 20 подходов: каждый получает отдельные поля повторений (или времени) и веса в кг. Вес можно оставить пустым для упражнений без отягощения. После добавления значения редактируются прямо в карточке и сохраняются автоматически. Нажмите название упражнения или число подходов, чтобы изменить название, количество подходов и их значения в диалоге. Нажмите «Подход N», чтобы изменить только его повторения и вес. Диалоги применяют изменения только после «Сохранить»; «Отмена» оставляет исходную запись. Уменьшение и повторное увеличение числа подходов в незакрытом диалоге сохраняет введённый черновик. Старые записи через `/` автоматически распределяются по подходам, если число значений совпадает с числом подходов; общий вес применяется ко всем. Исходный текст старых записей также сохраняется в данных. «Сегодня» и «вчера» определяются по локальному времени устройства.

## GitHub Pages

Workflow `.github/workflows/flutter-web.yml` при изменениях `main` устанавливает фиксированный Flutter SDK, запускает анализ и тесты, собирает сайт и записывает только готовую сборку в `gh-pages`, сохраняя историю ветки. В **Settings → Pages** остаётся источник **Deploy from a branch → gh-pages → / (root)**.

После записи сборки в `gh-pages` workflow явно запрашивает GitHub Pages build через API (разрешение `pages: write`). Ручной коммит публикации не требуется. Загрузчик Flutter и Dart-код получают имена с SHA сборки: браузер загружает новые файлы вместо старых из кеша. `source-revision.txt` показывает исходный коммит опубликованной сборки. Для диагностики и повторного запуска публикации доступен workflow `Verify and repair Pages publication`.
